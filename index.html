01 / THE IDEA

What problem does it solve?

Association Rule Learning searches transaction data for item combinations that occur together more often than expected under a chosen measure. A rule such as {tea} → {biscuits} means transactions containing tea are observed alongside biscuits at a certain rate. It describes co-occurrence, not proof that one item causes another or that a customer will buy it next.

Large baskets are difficult to inspect manually. Frequent-itemset mining and association rules summarise recurring combinations that may inform product placement, recommendations, bundles, or inventory planning. Useful rules must be judged by support, confidence, lift, sample size, and business context.

Support(A→B)=P(A∩B); Confidence(A→B)=P(A∩B)/P(A); Lift(A→B)=P(A∩B)/(P(A)P(B))

02 / METHOD

How it works, step by step

  1. 01
    Represent each transaction as a set of items.
  2. 02
    Choose minimum support to filter combinations that occur too rarely.
  3. 03
    Find frequent itemsets using a method such as Apriori or FP-Growth.
  4. 04
    Generate candidate rules from the frequent itemsets.
  5. 05
    Rank and inspect rules using confidence and lift; validate them on a later or separate sample where possible.

03 / VOCABULARY

Concepts worth knowing

Support

Fraction of all transactions containing every item in an itemset.

Confidence

Among transactions containing the antecedent, the fraction that also contain the consequent.

Lift

Confidence divided by the consequent’s overall support. Lift above 1 indicates positive association under this measure.

Antecedent

The left-hand side of a rule: the item or set of items used as a condition.

Consequent

The right-hand side: the item or set of items observed with the antecedent.

Frequent itemset

An item combination whose support meets the chosen minimum threshold.

04 / IN PRACTICE

A realistic use case

A grocery team could examine whether coffee and filters frequently occur in the same basket, then test a nearby placement or bundle. A high-confidence rule may simply reflect that the consequent is popular, which is why lift and transaction counts add context.

Questions to ask before trusting the result

  • Does the data represent the population or workflow where the model will be used?
  • Are important features missing, noisy, or measured after the outcome?
  • Would a wrong prediction have unequal costs for different groups?
  • Can the result be checked on data not used to build or tune the method?

07 / INTERPRETATION

How to interpret the output

Support answers how common the combination is overall. Confidence answers how often the consequent appears when the antecedent is present. Lift compares this rate with the consequent’s baseline frequency. A rule can have high confidence but low lift when its consequent is popular anyway.

Do not confuse a pattern with proof

A plot is evidence about the rows and variables it displays. It does not by itself establish causation, guarantee performance on future data, or show that a model will remain reliable after the data distribution changes. Document assumptions and evaluate the method in the context where it will be used.

08 / TRADE-OFFS

Strengths and limitations

Where it helps

  • Produces human-readable co-occurrence patterns
  • Useful for basket and sequence exploration
  • Support, confidence, and lift answer different questions
  • Can help generate hypotheses for controlled business tests

Where to be careful

  • Rules can be numerous and redundant
  • Rare combinations may be unstable
  • Association does not imply causation
  • Patterns may reflect seasonality, promotions, or customer mix

When should you use it?

Use it when data naturally consists of transactions or item sets. Prioritise rules that are frequent enough, interpretable, actionable, and validated—not merely the rules with the largest confidence.

10 / TAKEAWAY

What to remember

Use it when data naturally consists of transactions or item sets. Prioritise rules that are frequent enough, interpretable, actionable, and validated—not merely the rules with the largest confidence.

The best workflow is not simply to run an algorithm and show a graph. It is to define the question, prepare the data, explain the method, examine evidence, test limitations, and communicate what can reasonably be concluded.

11 / WORKED EXAMPLE

Worked example: confidence versus lift

If 70% of baskets contain milk, a rule that predicts milk with 75% confidence has only a modest lift of about 1.07. The confidence sounds high, but milk was already common. Lift compares the rule with the baseline frequency of its consequent, while support reveals how many transactions actually contain the combination.

  • Report support alongside confidence and lift.
  • Check the transaction count behind a rule, not only its ratio.
  • Treat discovered rules as hypotheses to test, not causal claims.

12 / REPRODUCIBLE WORKFLOW

Implementation blueprint

This optional Python example shows the usual workflow for the included CSV. It is source code for running locally, not code that runs inside this static article. Install the listed libraries first, keep the dataset file beside the script, and use the printed output as a starting point for interpretation—not as a substitute for checking assumptions.

import pandas as pd
from mlxtend.frequent_patterns import apriori, association_rules

df = pd.read_csv("market_basket_teaching_data.csv")
items = df.drop(columns=["transaction_id"]).astype(bool)
frequent = apriori(items, min_support=0.08, use_colnames=True)
rules = association_rules(frequent, metric="confidence", min_threshold=0.35)
rules = rules.sort_values(["lift", "confidence"], ascending=False)
print(rules[["antecedents", "consequents", "support",
             "confidence", "lift"]].head(10))

How to read it: the code selects the relevant columns, applies the algorithm, and prints a summary or evaluation. Results can vary with random sampling and package versions. For a real project, document the split, parameters, metrics, and any preprocessing choices.

13 / QUALITY CHECK

Common mistakes to avoid

  • Ranking rules only by confidence.
  • Ignoring rare combinations and small sample counts.
  • Describing co-occurrence as causation.

Before publishing a conclusion, ask whether the data supports the statement, whether the chart matches the stated method, and whether a reader could reproduce the workflow from the included files.
